# Managed Agents Console IA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rework the MandoForge console IA so Managed Agents is the core product surface, Workflow/Dynamic/Board are consolidated under Runs & Tasks, and System Ops clearly means platform operations.

**Architecture:** Keep backend routes and existing Yew component files compatible while changing the user-facing IA. Hide obsolete top-level entries through a new visible navigation list, route legacy view IDs to their new surfaces, and progressively enrich the existing `AgentsView`, `WorkflowsView`, `PacksView`, and `DeployView` instead of introducing a second shell.

**Tech Stack:** Rust, Yew, Trunk, existing MandoForge API polling, static `web/` bundle served by `mandoforge-api`, Chrome DevTools verification.

---

## Scope and Current Constraints

- Spec: `docs/superpowers/specs/2026-06-14-managed-agents-console-ia-design.md`
- Current nav truth: `web-ui/src/state.rs` still exposes 10 entries via `View::ALL`.
- Current shell truth: `web-ui/src/main.rs` imports and matches `AgentsView`, `BoardView`, `WorkflowsView`, `DynamicView`, `SemanticView`, `PacksView`, `DeployView`, and `SettingsView`.
- Current duplicated execution surfaces:
  - `web-ui/src/views/workflows.rs`: workflow definitions, runs, scheduler, evidence links.
  - `web-ui/src/views/dynamic.rs`: dynamic plan compiler, fleet shape, dynamic plans.
  - `web-ui/src/views/board.rs`: kanban task board, work items, manager plans/handoffs.
- Current Managed Agent surface: `web-ui/src/views/agents.rs` shows launcher, topology, queue, sessions, workflow runs, approvals, tool calls, version, logs.
- Current System Ops material: `web-ui/src/views/deploy.rs` and `web-ui/src/views/settings.rs`.

Important dirty-worktree note:

- At plan-writing time, the repo already contains uncommitted UI WIP and regenerated static assets from the prior console cleanup.
- Implementation must not revert unrelated user/WIP changes.
- Commit each implementation task atomically and stage only files touched by that task.
- `.superpowers/` brainstorming output is local support material and must not be staged.

  - Route old `Settings` and `Wizard` variants to `DeployView` or keep compatibility only if a direct old view is intentionally opened.

  - Align hero and task cards with the final six-entry IA.

- `web-ui/src/views/agents.rs`
  - Reframe as `Managed Agents / 托管智能体`.
  - Add Manager Agent observation/advice rail using existing `manager_plans`, handoffs, approvals, failed jobs, sessions, and tool-call data.

- `web-ui/src/views/workflows.rs`
  - Reframe as `Runs & Tasks / 运行与任务`.
  - Merge content from `dynamic.rs` and `board.rs` into internal tabs/sections.
  - Keep dynamic plan compile controls here.

- `web-ui/src/views/packs.rs`
  - Reframe visible copy as `Capabilities / 能力包`.
  - Explain what each pack enables for managed agents.

- `web-ui/src/views/deploy.rs`

  - Pull in or link settings/desktop/security readiness concepts.

- `web-ui/src/styles.css`

- `web/index.html`
  - Regenerated by Trunk.

- `crates/mandoforge-api/src/main.rs`
  - Update `CONSOLE_CONTENT_SECURITY_POLICY` script hash after Trunk rebuild.

### Do not modify unless needed

- Backend API routes.
- Store schemas.
- Desktop/Tauri code.
- Ontology builder backend logic.

#[derive(Properties, Clone, PartialEq)]
struct RunsTasksSummaryProps {
    data: ConsoleData,

#[component]
fn RunsTasksSummary(props: &RunsTasksSummaryProps) -> Html {
    let data = &props.data;
    let active_runs = data
        .workflow_runs
        .data
        .iter()
        .filter(|run| is_active_status(&run.status))
        .count();
    let failed_runs = data
        .workflow_runs
        .data
        .iter()
        .filter(|run| status_tone(&run.status) == "bad")
        .count();
    let blocked_tasks = data
        .task_board
        .data
        .items
        .iter()
        .filter(|item| board_column(&item.status) == "blocked")
        .count();
    let pending_approvals = data
        .approvals
        .data
        .iter()
        .filter(|approval| approval.status == "pending" || approval.status == "requires_action")
        .count();

    html! {
        <section class="runs-summary-grid">
            <FlowMeter label="运行中" value={active_runs} max={data.workflow_runs.data.len().max(1)} tone="info" />
            <FlowMeter label="失败运行" value={failed_runs} max={data.workflow_runs.data.len().max(1)} tone={if failed_runs > 0 { "bad" } else { "good" }} />

```rust
#[derive(Properties, Clone, PartialEq)]
struct ManagerObservationRailProps {
    data: ConsoleData,
}

#[component]
fn ManagerObservationRail(props: &ManagerObservationRailProps) -> Html {
    let data = &props.data;
    let idle_agents = data
        .agents
        .data
        .iter()
        .filter(|agent| !data.sessions.data.iter().any(|session| session.agent_id == agent.id && is_active_status(&session.status)))
        .count();
    let failed_jobs = data
        .execution_jobs
        .data
        .iter()
        .chain(data.session_loop_jobs.data.iter())
        .filter(|job| status_tone(&job.status) == "bad" || job.last_error.is_some())
        .count();
    let pending_approvals = data
        .approvals
        .data
        .iter()
        .filter(|approval| approval.status == "pending" || approval.status == "requires_action")
        .count();

    let mut observations = Vec::<(String, String, String)>::new();
    if idle_agents > 0 {
        observations.push(("neutral".to_string(), "空闲智能体".to_string(), format!("{idle_agents} 个智能体当前没有活跃 session")));
    }
    if failed_jobs > 0 {
        observations.push(("bad".to_string(), "失败任务".to_string(), format!("{failed_jobs} 个执行或 session-loop 任务失败")));
    }
    if pending_approvals > 0 {
        observations.push(("warn".to_string(), "待审批".to_string(), format!("{pending_approvals} 个动作需要人工确认")));
    }
    if observations.is_empty() {
        observations.push(("good".to_string(), "状态正常".to_string(), "Manager 没有发现需要立即处理的阻塞。".to_string()));
    }

    html! {
        <aside class="manager-observation-rail">
            <header>
                <span>{ "Manager Agent" }</span>
                <strong>{ "观察与建议" }</strong>
            </header>
            <KeyMetrics values={vec![
                ("Manager plans".to_string(), data.manager_plans.data.len().to_string()),
                ("Handoffs".to_string(), data.agent_handoffs.data.len().to_string()),
                ("Assignments".to_string(), data.agent_handoff_assignments.data.len().to_string()),
            ]} />
            <Rows empty="Manager 没有观察结果。" rows={observations} />
            <p>{ "默认只提出建议；写操作和高风险动作仍需要 policy 与 approval。" }</p>
        </aside>
    }
}
```
