# Store Profile

Generated by the `profile-onboarding` workflow. A tenant store profile must be
filled before any customer-service, review, after-sales, or media workflow is
released.

Required sections:

- Store identity: `tenant_id`, `workspace_id`, `shop_id`, `store_name`,
  `seller_nick`, `primary_category`, `secondary_categories`.
- Brand voice: tone, formality, banned wording, preferred apology style, and
  allowed compensation language.
- Customer-service policy: service hours, response SLA, escalation owners,
  pre-sale boundaries, post-sale boundaries, and platform-dispute handling.
- After-sales policy: refund-only, return-and-refund, exchange, damaged item,
  missing item, logistics dispute, and evidence requirements.
- Logistics policy: carrier list, promiseable delivery language, non-promiseable
  delivery language, warehouse cut-off time, and holiday exceptions.
- Review policy: public explanation style, private recovery options, forbidden
  buyer-blaming phrases, and personal-data redaction rules.
- Content policy: allowed claims, prohibited claims, product-evidence sources,
  required disclaimer language, and approval owner for media uploads.
- Channel capability map: TOP read/write availability, QianNiu task
  availability, operator-import batch availability, browser-assisted import
  availability, media upload permission, and product-edit permission.
- Campaign calendar: promotion name, active window, affected SKUs, discount
  terms, customer-service notes, and content restrictions.

Readiness rule:

- Missing customer-service, after-sales, review, content, approval, or connector
  policy blocks release for the dependent workflow lane.
- Missing optional channel capability degrades only the affected workflow lane.
- Raw buyer messages, review text, refund records, and order details remain
  scoped to `domain_scope=ecommerce`, `workflow_scope=tmall`,
  `share_policy=isolated`.
